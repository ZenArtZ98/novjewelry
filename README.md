# НОВЬ

Лендинг бренда украшений, перенесённый из предоставленного standalone-прототипа в **React 18 + Vite**. Сохранены исходные фотографии, шрифты, SVG-формы, цвета, тексты, размеры, адаптивные правила и анимации. В браузере больше не выполняются распаковка HTML, компиляция шаблонов и загрузка движка прототипа.

## Запуск

Нужен Node.js 22.13+ в ветке 22 LTS либо Node.js 24+.

```sh
npm ci
npm run dev
```

Адрес разработки: `http://127.0.0.1:5173`.

Для GitHub Pages в репозитории есть workflow: push в `master` собирает сайт и публикует его через Pages по адресу `https://zenartz98.github.io/novjewelry/`. В настройках репозитория один раз выберите **Settings → Pages → Source: GitHub Actions**. Позже можно подключить собственный домен в настройках Pages.

```sh
npm run build
npm run preview
```

Готовый сайт находится в `dist/`. Сборка заранее генерирует HTML с содержимым лендинга; React подключает интерактивность поверх него. Постоянный сервер React, база данных и внешние CDN не требуются. `npm run preview` запускает проверочный HTTP-сервер на `http://127.0.0.1:4173` с настоящими 404 и заголовками безопасности. Он слушает только локальный интерфейс и не предназначен для публичного размещения.

## Подготовка к публикации

`npm run build` создаёт тестовую сборку: `noindex` в HTML и HTTP-заголовках, `Disallow: /` в `robots.txt`. Домен не придумывается, поэтому без production-режима `sitemap.xml` не создаётся. Это ограничение индексации, а не защита доступа к тестовому сайту.

1. Скопируйте `.env.example` в `.env.local` и заполните `SITE_URL` реальным HTTPS-адресом публикации. Допустим необязательный путь, но нельзя указывать параметры, порт или hash.
2. Выполните `npm run check`. Команда проверяет тестовую сборку, исходную геометрию и интерактивность.
3. Выполните **`npm run build:release`**. Без домена эта команда завершится с понятной ошибкой. Она включает индексацию и генерирует canonical, `og:url`, `robots.txt` и `sitemap.xml` с единственной реальной страницей — главной. Якоря секций и страница 404 в sitemap не входят.
4. Опубликуйте содержимое `dist/`. Для Nginx также скопируйте `.build/security-headers.conf` и подключите `deploy/nginx-site.conf` внутри своего HTTPS server-блока, проверив пути. Файл `dist/_headers` предназначен для статических платформ, которые поддерживают этот формат; на обычном Nginx сам по себе он ничего не настраивает.
5. На выбранном хостинге настройте сертификат, редирект HTTP → HTTPS и один основной домен (второй вариант, например www, должен перенаправляться на него). Настройте выдачу `/404.html` со статусом **404** для неизвестных адресов. Не включайте перенаправление всех URL на главную с кодом 200.

После публикации проверьте `/`, `/robots.txt`, `/sitemap.xml`, произвольный отсутствующий адрес и вкладку Network браузера. Затем можно добавить сайт в Google Search Console и Яндекс Вебмастер. Домены, DNS, сертификат и серверные настройки применяются у выбранного провайдера; локальная сборка не изменяет их автоматически.

В проект добавлены SVG-иконка из оригинального знака бренда, отдельная статическая 404, Open Graph/Twitter-метаданные, предварительная загрузка основных шрифтов, CSP, запрет MIME-sniffing и встраивания во фреймы, Referrer-Policy, Permissions-Policy и правила кеширования. HSTS не включён автоматически: его настраивают после проверки HTTPS на основном домене. Иконка и страница 404 работают без JavaScript. Карточки и фильтры требуют JavaScript; содержимое каталога доступно и без него.

При добавлении аналитики, сторонних шрифтов или виджетов необходимо обновить CSP в `scripts/headers.js`. Сейчас он допускает только локальные скрипты и ресурсы; inline-стили разрешены для исходных React-анимаций.

## Структура

```text
public/assets/
  fonts/               Оригинальные Belarus, Montserrat, Roboto Serif
  images/              Оригинальные фотографии WebP
src/
  components/sections/ Секции страницы и их CSS
  components/ui/       Логотип и кнопка связи
  animations/          Физика фигур, курсор и фотолента
  hooks/               Состояние страницы, эффекты и управление диалогом
  data/                Каталог, материалы, фотолента, FAQ и тексты шагов
  config/contacts.js    Адреса сообщества и соцсетей
  styles/              Токены, типографика, маски, общие правила
  utils/               Формирование путей к ресурсам
  App.jsx              Композиция страницы
  main.jsx             Точка входа
tests/                 Проверки интерактива и исходных размеров секций
scripts/               Сборка HTML, SEO-файлы, HTTP-превью и заголовки
deploy/                Настройки Nginx
public/404.html        Страница ошибки без зависимости от React
```

CSS оставлен обычным: перевод на Tailwind здесь не улучшал бы результат и усложнил бы сохранение точных стилей. Статические правила вынесены из разметки, динамические значения задаются React. Анимации используют исходные кривые, длительности и формулы движения; обработчики, наблюдатели, таймеры и animation frame освобождаются при размонтировании.

## Редактирование

- Товары, цены, описания и соответствие фотографий: `src/data/products.js`.
- Материалы и FAQ: `src/data/materials.js`, `src/data/faq.js`.
- Карточки первого экрана и фигуры: `src/data/hero.js`.
- Фотолента: `src/data/gallery.js`.
- Цвета, шрифты и основные переменные: `src/styles/tokens.css`.
- Стили отдельной секции: CSS рядом с соответствующим JSX-компонентом.
- Контакты: `src/config/contacts.js`. Кнопки связи и ссылка ВК ведут на предоставленное сообщество `https://vk.ru/novi_jewelry`. Telegram и Pinterest пока не предоставлены и сохраняют исходный переход к секции контактов. Для подключения достаточно заполнить два поля.

Это лендинг с каталогом и обращением в сообщество. Корзины, оплаты и обработки заказов на сервере в исходнике нет; эти возможности не добавлялись.

## Проверки

```sh
npx playwright install chromium
npm run check
```

Отдельно доступны `npm run lint`, `npm run format:check`, `npm run build` и `npm test`.

Перед отдельным `npm test` выполните `npm run build`: тесты используют и сервер разработки, и готовую тестовую сборку. Тесты проверяют загрузку ресурсов, фильтры, карточки товаров, управление фокусом, закрытие диалога, FAQ, смену материала, фотоленту, уменьшение движения и четыре размера экрана. Размеры секций сравниваются с измерениями исходного прототипа, сохранёнными в `tests/fixtures/original-layouts.json`. Отдельно проверяются готовый HTML, гидратация без ошибок CSP, работа без JavaScript, HTTP 404, кеширование, редирект `/index.html`, запрет индексации превью и генерация production robots/sitemap.

Для справки: [ошибки soft 404 у Google](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics), [спецификация robots.txt](https://developers.google.com/crawling/docs/robots-txt/robots-txt-spec).

При переносе выполнено сравнение полных скриншотов исходника и React-версии на экранах 1440×900, 1024×768, 390×844 и 360×800. Для воспроизводимого сравнения движение замораживалось в одной фазе. Геометрия всех секций совпала; максимальное различие пикселей составило около 0,011% при пороге сравнения 0,15. Это проверка в Chromium, а не гарантия идентичного рендеринга во всех браузерах.

Улучшения без изменения обычного оформления: язык документа и метаданные, блокировка фоновой прокрутки и управление фокусом в диалоге, корректное отображение текста при `prefers-reduced-motion`.
